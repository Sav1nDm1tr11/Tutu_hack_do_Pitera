# 00. Бриф хакатона (выжимка из официальной презентации)

Источник: «Хакатон туту 2026.pdf», 12 слайдов. Всё ниже — цитаты/факты, не выводы.

## Формат

- 71 команда, 150 участников. Старт разработки — 19.08.2026, 10:40.
- **Окончание 19.08 в 21:00 — сдача исходников. После 21:20 работы не принимаются.**
- Питчинг 20.08, 11:00–16:00, три стрима (25/25/21 команда), по 3 судьи на стрим
  (два технических + один продуктовый). **10 минут на команду, тайминг жёстко
  фасилитируется**, вопросы судей — в конце.
- 21.08: по 3 лучших из стрима → 9 команд во второй этап, в 15:00 объявление итогов.
  **Прототипы не выключать до 21.08.**

## Что сдаём (три ссылки)

1. Ссылка на работающий прототип (для мобилки — сборка).
2. Ссылка на пользовательскую документацию — «ей уделяем внимание».
3. Ссылка на репозиторий проекта, плюсом — документация к коду.

> «Обязательно проверьте доступность всех ссылок (если во время проверки что-то
> не будет работать — не засчитаем материал)».

## Критерии оценки — 100 баллов

| Блок | Критерий | Баллы |
|---|---|---|
| Продукт (80) | Понимание задачи и соответствие теме | 10 |
| | Глубина проработки функционала | 15 |
| | **Качество UX/UI** | **20** |
| | Презентация | 5 |
| | Проработка документации — AI-проверка | 10 |
| | Инновационность технологий | 10 |
| | Стабильность работы | 10 |
| Техника (20) | Архитектура приложения — AI-проверка | 10 |
| | Качество кода — AI-проверка | 10 |

Пункты с пометкой «AI-проверка» дополнительно оцениваются AI-анализом
документации, архитектуры и кода. **Вывод: README/доки/ARCHITECTURE.md — это
не бюрократия, а 30 баллов из 100.**

## Задание

> «Любой продукт на базе нашего MCP: https://mcp.tutu.ru/mcp. Документация — по
> этой же ссылке. Не ограничивайте полёт фантазии, голосовые помощники утомляют.
> Проведите исследование, проанализируйте, что действительно могло бы встряхнуть
> рынок тревела.»
> Акценты: «свежий взгляд на сервис путешествий», «интерфейсное решение», «упор
> на необычность решения — не бойтесь экспериментов».

## Что из этого следует для нас

1. UX/UI (20) + глубина (15) = 35 баллов, поэтому центр тяжести — интерфейс и
   продуктовая логика, а не бэкенд.
2. Стабильность (10) стоит столько же, сколько инновационность → demo mode и
   graceful degradation обязательны.
3. Документация (10) + архитектура (10) + код (10) = 30 баллов и всё это читает
   AI → пишем машиночитаемо: чистая структура, README, ADR, типы, комментарии «почему».
4. 10 минут питча = ~3 минуты демо. Сценарий демо репетируем, см. `07-demo-script.md`.
