# Handoff: материалы ревью и продуктовые спеки

Эта папка — **сопроводительные материалы**, а не описание того, как устроен код.
Реализация описана в `docs/ARCHITECTURE.md` и `docs/SPEC.md`, состояние качества —
в `docs/wiki/`.

| Файл | Что это | Статус |
|---|---|---|
| `00-hackathon-brief.md` | Условия хакатона: тайминг, критерии оценки, что сдаём | факт, из официальной презентации |
| `01-mcp-reference.md` | Справочник по Tutu MCP: 16 инструментов, форма ответов, правила сервера | **проверено вживую 19.08.2026**, не догадки |
| `02-ux-spec.md` | ТЗ дизайнеру: экраны, состояния, тон | предложение |
| `03-scoring-alternative.md` | Альтернативная модель индекса устойчивости (5 компонент, 100 баллов) | **не реализована**; в коде своя модель размерностей с confidence, см. `packages/domain/src/scoring/` |
| `04-demo-script.md` | Сценарий 10-минутного питча и ответы судьям | предложение |
| `05-product-positioning.md` | Позиционирование, истории, MoSCoW | предложение |
| `06-design-prompt.md` | Готовый промпт для Claude Design, фиолетовая палитра | инструмент |

## Как этим пользоваться

- Перед работой с MCP — читать `01-mcp-reference.md`. Он избавляет от главной
  ошибки: выдуманных полей ответа.
- Перед питчем — `00-hackathon-brief.md` (критерии) и `04-demo-script.md`.
- Дизайнеру — `02-ux-spec.md` + `06-design-prompt.md`.
- `03-scoring-alternative.md` держать как справочник идей, но **не выдавать за
  реализацию**: числа в интерфейсе считает код из `packages/domain/src/scoring/`.
